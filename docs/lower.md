## 0. 下層在做什麼

給定一段**已經換算到這具身體上的參考動作**，訓練機器人去追它。

三個要學的網路（合稱 φ）：

| 網路 | 輸入 | 輸出 | 做什麼 |
|---|---|---|---|
| `LatentAdapter` | 身材 β、意圖 z0 | z_β (256) | 告訴凍結 AI「你現在在一個不一樣的身體裡」|
| `ActionHead` | 凍結 AI 的動作、β | 69 個關節指令 | 微調凍結 AI 的輸出 |
| `RootWrenchHead` | 根部狀態、β | 6 維外力 | **訓練用的拐杖**，最後退火到零 |

中間夾著**完全凍結**的 Meta Motivo。

## 1. 策略長什麼樣

```
z_β    = project( z0 + α · MLP_adapter([β, z0]) )         α = 0.05
raw    = frozen_actor( normalize(obs), z_β )              (69,)  ← 可微，梯度能經 z_β 回傳
μ_ctrl = ActionHead(raw, β)                               (69,)
μ_wr   = RootWrenchHead([root_feats, β, raw])             (6,)

a ~ N( [μ_ctrl, μ_wr],  σ )                σ_ctrl = σ_wrench = 0.05
```

### `project` 是什麼、為什麼必要

凍結 AI 只認得**長度剛好 16**（= √256）的意圖向量 —— 它訓練時看到的所有 z 都在那個球面上。

```python
z_β = 16 * F.normalize(z0 + α·delta)
```

少了這一行就是餵它沒見過的輸入。這是舊系統實測出來的缺陷（所有存檔的 z norm 都剛好 16.0，但 `model/networks.py` 回傳未投影的值）。

### `α = 0.05` 是什麼

修正的幅度。`z_β = z0 + 0.05 × 修正`，也就是「以 z0 為主，只微調」。從舊系統的 0.1 降下來的。

### `raw` 為什麼可微

程式碼刻意呼叫 `model._normalize` / `model._actor`，而不是被 `@torch.no_grad()` 包住的 `model.act()`。凍結 AI 的**權重**不更新，但梯度要能**穿過它**回到 `LatentAdapter`。

### `a ~ N(μ, σ)` 是什麼意思

策略不是直接輸出動作，而是輸出一個**高斯分布的中心** `μ`，再從 `N(μ, 0.05²)` 抽樣。抽樣提供**探索** —— 沒有隨機性就沒有東西可以比較「這樣做比較好還是那樣做比較好」。

75 維（69 + 6）合成一個高斯，在 **squash 之前**抽樣。worker 端才套：

```python
ctrl   = clip(a[:69], −1, 1)            MuJoCo 本來就會夾
force  = f_max · tanh(a[69:72])
torque = m_max · tanh(a[72:75])
```

PPO 的 log-prob 用**未 squash** 的值，所以它就是一個純高斯，不需要 tanh 的 Jacobian 修正。

### 外力是拐杖不是交付物

根部是自由關節，**沒有馬達**（`nv=75` 但 `nu=69`，差的 6 個就是它）。所以動作空間裡沒有任何東西能直接阻止機器人倒下。`RootWrenchHead` 給它一隻「隱形的手」。

```
f_max = 0.5 · M · g       iteration 0–2000 固定
        ↓ cosine 退火
        0                 iteration 8000
```

**所有回報的 eval 數字一律在 `f_max = 0` 下量測，從 iteration 1 開始就是。**

輸出在**根部自己的座標系**，主進程用當前的根部四元數旋到世界座標再寫進 `xfrc_applied`。這讓這個 head 對旋轉是等變的 —— 同樣的前傾產生同樣的扶正力，不管人面向哪邊。

## 2. 每一步的獎勵

worker 在模擬完之後，從 `data.qpos / qvel / xpos / actuator_force / contact` 加上參考幀算出來。

```
r_t = 0.65 · r_track + 0.15 · r_reg + 0.20 · r_surv          有界於 [0, 1]
```

### `r_track` — 追不追得上

```
r_pose = exp( −2.0   · (1/69) Σ_j (q_j − q̂_j)² )
r_vel  = exp( −0.005 · (1/69) Σ_j (q̇_j − q̂̇_j)² )
r_ee   = exp( −40    · (1/5)  Σ_e ‖(p_e − p_root) − (p̂_e − p̂_root)‖² )
r_root = exp( −10    · ( ‖p_root − p̂_root‖² + 0.5·‖log(q̂_root⁻¹ ⊗ q_root)‖² ) )
r_com  = exp( −10    · ‖com_xy − ĉom_xy‖² )

r_track = 0.35 r_pose + 0.15 r_vel + 0.25 r_ee + 0.15 r_root + 0.10 r_com
```

**符號**：戴帽子的 `q̂` 是**參考**的值，沒帽子的 `q` 是**機器人實際**的值。`p_e` 是末端（雙手雙腳頭）的位置，`com` 是質心。

**`exp(−k · 誤差²)` 這個形式叫指數核（DeepMimic 式）**。它把「誤差」轉成「獎勵」：

| 誤差 | `exp(−2·誤差)` |
|---|---|
| 0（完美）| 1.0 |
| 0.35 | 0.5 |
| 大 | → 0 |

好處是**有界在 (0, 1]**，對 value network 的尺度很友善（後面會看到為什麼重要）。係數 `k` 決定「多大的誤差算差」。

**`r_ee` 減掉 root** 是有意的：比的是「手相對於身體在哪」，不是「手在世界的哪裡」。這樣即使整個人漂掉了，姿勢對不對仍然量得到。

**`r_root` 的第二項** `‖log(q̂⁻¹ ⊗ q)‖²` 是兩個朝向之間的**測地角度**平方。`q̂⁻¹ ⊗ q` 是「從參考朝向轉到實際朝向」的那個旋轉，取 log 得到它的軸角表示，長度就是轉了幾弧度。

> **`r_pose` 用原始弧度，不除以關節活動範圍。** 那 12 個活動範圍只有 0.16–0.30 rad 的近乎鎖死關節，一旦正規化就會主宰誤差，但它們對視覺幾乎沒貢獻。用原始弧度時它們自然自限，因為物理本來就會夾住。

### `r_reg` — 有沒有用旁門左道

```
e_act    = (1/69)‖a‖²                          動作大小
e_smooth = (1/69)‖a_t − a_{t−1}‖²              抖動
e_res    = (1/69)‖a − raw_prior‖²              離凍結 AI 多遠
e_tau    = (1/69) Σ_j (力矩_j / forcerange_j)²  馬達吃力程度
e_ext    = ‖f‖²/(Mg)² + ‖m‖²/(Mg·L_leg)²       外力大小
e_slip   = Σ_{接觸中的腳} ‖v_foot,xy‖²           腳滑

r_reg = exp( −( 0.1 e_act + 1.0 e_smooth + 0.5 e_res + 0.5 e_tau + 8.0 e_ext + 2.0 e_slip ) )
```

一樣用指數包住，所以 `r_reg ∈ (0, 1]`。

**`e_ext` 的 8.0 是全場最大** —— 外力是滿足其他所有項最便宜的路徑，必須讓它貴。

**`e_ext` 的分母是 `(Mg)²` 和 `(Mg·L_leg)²`** —— 這樣不同體重的身體是按**體重的比例**被罰，不是按絕對牛頓數。小孩用 20 N 和巨人用 20 N 不是同一回事。

**`e_slip` 用真實接觸偵測**（`data.contact`），不是「腳低於 0.05 m 就算著地」的高度近似。worker 手上有 MjData，這是舊的 post-hoc 版本拿不到的資訊。

### `r_surv` — 還活著沒

```
r_surv = 1 如果活著，0 如果死了（並終止這個 window）

alive =  root_z    > 0.5 · ẑ_root,t                          沒垮下去
      ∧  up_z      > ûp_z − 0.8                              沒比參考翻得更倒
      ∧  ‖p_root − p̂_root‖ < 0.75 · (L_leg/L_leg,adult)      沒飄走
      ∧  (1/69) Σ_j (q_j − q̂_j)² < 0.6                       沒追丟
```

四個條件裡有三個是**相對參考**的，這很重要：

> **`up_z` 的判定必須相對參考姿態。** 資料集裡 21% 的影格本來就不直立（倒立、爬行、躺著），絕對門檻會把「正確做出倒立」判成跌倒 —— 實測這曾經是 Stage 1 過不了的主因。

> **`up_z = 2(q_y q_z + q_w q_x)`，不是教科書的 `1 − 2(qx²+qy²)`。** 這個資產的骨盆帶 `euler="90 0 0"`，靜止四元數是 `(0.7071, 0.7071, 0, 0)`，局部 **+Y**（不是 +Z）對應世界的上方。

**「追蹤失敗也算終止」是 motion tracking RL 裡槓桿最大的一招** —— 少了它，`r_surv` 幾乎恆等於 1，變成常數，完全不帶訊號。

### worker 回傳的是 14 個未加權的數字

不是一個純量獎勵。兩個理由：

1. ES 估計器必須能**不重跑模擬**就重新加權 `F_sim`
2. 獎勵權重掃描變成免費

加權在主進程做（`rewards.combine`）。

## 3. 從獎勵到梯度：PPO

### 為什麼需要「轉換」

`r_t` 是模擬器算出來的數字，**對策略參數沒有梯度** —— 中間隔著一個不可微的物理引擎，你沒辦法對「跌倒了」做 `.backward()`。

PPO 的工作就是把獎勵轉成一個**有梯度的替代目標**。

### 第一步：折扣回報

```
G_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + ...          γ = 0.97
```

**`γ = 0.97` 是怎麼挑的**：有效視野約 `1/(1−γ) = 33` 步 ≈ 1.1 秒。比一個 window（60 步 = 2 秒）短，但足以讓「站穩再走」這種需要一秒的行為被賦值。訓練前 1000 iteration 先用 `γ = 0.95`（更短視、更好學），之後才調到 0.97。

### 第二步：優勢（advantage）

```
A_t = 「實際拿到的」 − 「預期會拿到的」
```

「預期」由一個 **value network** `V(s)` 提供。`A_t > 0` 表示這個動作比平均好 → 加強它；`< 0` → 抑制它。

**為什麼要減掉 V**：不減的話，一段本來就容易的動作，每個動作都會拿到高回報、全部被加強，即使其中有些其實很爛。減掉基準線之後留下的才是「這個動作本身的貢獻」。

### GAE：怎麼估 `A_t`

```
δ_t = r_t + γ·V(s_{t+1}) − V(s_t)                     單步的「意外程度」
A_t = δ_t + (γλ)·δ_{t+1} + (γλ)²·δ_{t+2} + ...        λ = 0.95
```

| 極端 | 效果 |
|---|---|
| `λ = 0` | `A_t = δ_t`，完全信任 V。偏差大、變異小 |
| `λ = 1` | 完全用實際結果。偏差小、變異大 |
| `λ = 0.95` | 折衷 |

### 截斷 vs 終止 —— 不能搞混

| 情況 | 怎麼處理 | 為什麼 |
|---|---|---|
| **t = 60，window 到了** | **截斷**：用 `V(s_60)` 補上「後面還沒發生的部分」 | 故事沒完，只是我們不看了 |
| **跌倒 / 追丟** | **終止**：補 0，之後所有步從 loss 中 mask 掉 | 故事真的結束了 |

搞混會教壞策略 —— 讓它以為「活到一個任意 2 秒切片的結尾」毫無價值。

### 第三步：PPO 的替代目標

```
ratio_t = π_new(a_t | s_t) / π_old(a_t | s_t)

L_clip = −E[ min( ratio · A,  clip(ratio, 0.8, 1.2) · A ) ]
```

| 符號 | 意思 |
|---|---|
| `π_old` | 蒐集這批資料時的策略 |
| `π_new` | 現在正在更新的策略 |
| `ratio` | 「新策略選這個動作的機率，是舊策略的幾倍」 |
| `clip(·, 0.8, 1.2)` | 夾在 ±20% 之內 |

**`min` 和 `clip` 在做什麼**：如果某個動作很好（`A > 0`），策略會想大幅提高它的機率 —— 但 `clip` 讓 ratio 超過 1.2 之後**再提高也沒有額外獎勵**，梯度歸零。這就是「信賴域」：一次更新不准走太遠。

**為什麼需要它**：這個策略是「強凍結先驗上的 residual」，一次壞更新就毀掉先驗。PPO 的 clip 基本上是免費保險。

### 一個 iteration 的更新細節

```
15360 個 transition (= 256 envs × 60 步)
   ↓
重複 4 遍（epoch），每遍切 4 個 minibatch（各 3840）
   ↓
clip ε = 0.2、value clip 0.2、梯度範數上限 10.0
```

**`z_β` 在每個 minibatch 內用當前的 adapter 重算**，不是沿用蒐集時的值。adapter 是**策略的一部分**，PPO 的 ratio 必須反映它的更新 —— 不能把它當成凍結的 context 向量。

## 4. Value network

```
V( obs, z_β.detach(), β, phase )        phase = (t/H, (H−t)/H)
```

**`phase` 不可省。** window 會在 t = H 被截斷，value 必須知道「我離結尾多近」，否則 t = H 的 bootstrap 尺度會系統性地錯。

**`z_β.detach()`** —— value 的梯度不回傳到 adapter。value 是輔助設施，不該去改策略。

### 兩層正規化

**per-(clip, body) 的 advantage 正規化。** 有些 (動作, 身體) 組合就是比別的難，全域基準線會把這種**異質性**誤讀成 advantage。對每個 pair 維護 advantage 均值/標準差的 EMA（momentum 0.99），在 pair 內標準化。

> 這裡踩過一個實測的坑：早期版本拿 **episode 回報**的統計去正規化 **per-step advantage**。量級差 50 倍（回報約 5.5、per-step advantage 約 0.1），而且某個 pair 第一次出現時變異數恆為 0、標準差夾到 1e-3 → 除以它等於乘 1000。結果那個「advantage」編碼的是「這是哪個 pair」而不是「這個動作好不好」。

**value target 的 running 正規化（PopArt-lite）。** H = 60 時 `t=0` 的回報有相當比例來自 bootstrap，V 早期尺度錯掉會讓 GAE 變垃圾。另外前 **100 個 iteration 只訓練 value**（策略凍結），讓它先站穩。

## 5. 總 loss：四項

```
L = L_clip  +  0.5·L_value  +  λ_z·mean(1 − cos(z_β, z0))  +  λ_bc(k)·mean‖μ_ctrl − a_ref‖²
```

| 項 | 值 | 從哪來 |
|---|---|---|
| `L_clip` | — | 獎勵**轉換**來的（高變異，但懂物理因果）|
| `L_value` | 0.5 | 訓練 value network |
| `λ_z` | 0.1 | 錨定項，**繞過環境**的解析梯度 |
| `λ_bc` | 100 → 0 | 行為複製，**繞過環境**的解析梯度 |

### 為什麼有些東西放 loss、有些放 reward

判斷標準很乾脆：

| 這一項要知道什麼 | 放哪裡 |
|---|---|
| 模擬之後發生什麼事（跌倒沒、腳滑沒、馬達多吃力）| **只能是 reward** |
| 只看網路的輸出本身（`μ` 離 `a_ref` 多遠、`z_β` 離 `z0` 多遠）| **可以是 loss** |

而「可以放 loss」就一定要放 loss：放 reward 的話它得走一遍 score-function 估計（變異隨 75 維動作空間成長，而且只知道「這次結果比較好」，不知道「往哪個方向改」）；放 loss 是**精確的解析梯度** `∂‖μ−a_ref‖²/∂μ = 2(μ−a_ref)`，零變異，直接告訴每個關節該往哪邊調多少。

### `λ_z` — 別讓 z 飄走

```
1 − cos(z_β, z0) = 1 − ⟨ẑ_β, ẑ_0⟩
```

用 **cosine** 而不是歐氏距離：`z` 已經被投影到半徑 16 的球面上，歐氏範數會去懲罰一個**由建構固定**的半徑。cosine 才是那個球面上正確的距離。

而且是對 minibatch 內**唯一的 (clip, body) pair** 算，不是 per-transition —— 否則會被「哪個 pair 抽到比較多 window」隱性加權。

### `λ_bc` — 免費的正確答案

因為致動器是 affine 位置伺服，`ctrl ∈ [−1,1] ⟺ 關節角 ∈ jnt_range` **精確成立**（實測誤差 4.4e-16），所以「能命令出參考下一幀關節角的那個 ctrl」有封閉解：

```
a_ref,t = clip( 2·(q̂_{t+1} − lo)/(hi − lo) − 1 ,  −1, 1 )
```

`lo`/`hi` 是該關節的活動範圍。這條式子就是把 `[lo, hi]` 線性映射到 `[−1, 1]`。

**這是一條稠密、精確、零變異的梯度直接進 `ActionHead`**，條件數遠優於 PPO 能產出的任何東西。

> **`λ_bc = 100` 不是隨便挑的。** 實測 BC 的梯度範數是 0.15，PPO 的是 8–23 —— 在 `λ_bc = 1` 時 BC 只佔更新方向的 **1%**，3200 次更新後 BC 誤差還停在 0.75（比輸出全 0 的 0.31 還糟）。而 `ActionHead` 本身完全有能力擬合：純 BC 在固定 batch 上 250 步就到 0.06。100 讓兩個梯度同量級。

**但必須退火到零**（iteration 0–2000 cosine）：長期開著會與凍結先驗對抗，而且它**忽略動力學** —— 讓伺服**停在** `q̂` 的位置目標，不等於在負載下**驅動你到達** `q̂` 的目標。

### 梯度範數上限 10.0

實測 PPO 那一項的梯度範數是 8–23。這不是病態 —— `∂log p/∂μ = (a−μ)/σ²`，σ = 0.05、75 維，本來就這麼大。

但上限設 1.0 的話**每一步都被縮小約 15 倍**，等於是 clip 而不是 `lr_lower` 在決定步長。10.0 讓 clip 回到它該做的事：抓住偶爾一次會毀掉凍結先驗的離群更新。

## 6. 一次迭代的完整流程

```
1. 抽 256 組 (clip, body, t0)
2. RetargetNet(β) → u → apply_retarget → ref              上層產生參考
3. RSI：把 256 個模擬的姿勢寫成 ref[0]（關節加高斯噪音）
4. for t in 0..59:
       obs → LatentAdapter → 凍結 AI → ActionHead → ctrl
                                    └→ RootWrenchHead → wrench
       SimPool 走一步（15 個物理步 = 1/30 秒）
       worker 算 14 個未加權的獎勵項
5. rewards.combine → per-step reward
6. GAE → advantage
7. PPO：4 epochs × 4 minibatches
8. （每 10 輪）上層更新 p
```

約 2.9 秒（256 envs、60 步、9 具身體）。

## 7. 為什麼不用別的做法

| 替代方案 | 為什麼不 |
|---|---|
| **episode-level REINFORCE**（舊系統）| 在 `300 × 69 = 20700` 個抽樣維度上只給**一個純量**訊號。縮短 window 只會讓每樣本的訊噪比**更差** —— 成本的尺度縮小了，但 score function 的量級沒有 |
| **A2C** | 每 iteration 15360 個 fresh on-policy 樣本下可行，但這是「強凍結先驗上的 residual」，一次壞更新就毀掉先驗。PPO 的 clip 基本上是免費保險 |
| **backprop through time** | 沒有可微模擬器（無 MJX、無 jax）。進入 `z_β` 的解析路徑是真的，但它止於第一次 `env.step` |

## 8. 已知的限制

**訓練永遠是 60 步的 window，而且每個 window 都從參考重新 RSI。**

所以誤差不會跨 window 累積 —— 但部署時沒有這個重置。實測同一個策略、同一段動作、同一具身體：

```
訓練（每 60 步重新對時）     存活 22.3 / 24 步  = 93%
長 rollout（一路不對時）     存活 22 / 299 步   =  7%
```

這個缺口在 W&B 的 `long/` 面板上可以看到（每 100 iteration 跑一次 299 步、`f_max = 0` 的連續 rollout）。

根本原因是**獎勵是逐幀的** —— `r_pose` 比的是「這段軌跡的第 t 幀」，依賴一個外部時鐘。落後之後那個目標就變成不可滿足的，而策略連「自己落後多少」都觀測不到。試過用穩態的 AMP 風格獎勵取代，[失敗了並記錄在 `model/bilevel/amp.py`](../model/bilevel/amp.py)。**這個問題目前沒有解決。**
