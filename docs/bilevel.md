# 兩層是怎麼耦合的（proposal §4 的白話版）

程式碼：[`model/bilevel/upper.py`](../model/bilevel/upper.py)、[`model/bilevel/train_bilevel.py`](../model/bilevel/train_bilevel.py)

這份文件假設你**沒有**修過最佳化理論。每個式子都會逐符號解釋。

---

## 0. 先講整件事的形狀

我們有兩個東西要學：

| | 符號 | 是什麼 | 它想要什麼 |
|---|---|---|---|
| **下層** | φ (phi) | 策略 —— 機器人怎麼動 | **盡量貼近**參考動作 |
| **上層** | p (p) | 參考動作長什麼樣 | 讓這個「貼近」的差距**盡量小** |

問題在於：**上層的目標，取決於下層學成什麼樣；而下層學成什麼樣，又取決於上層給的參考。** 兩個互相依賴。

這種「一個最佳化問題的答案是另一個最佳化問題的輸入」的結構，叫做 **bilevel（雙層）最佳化**。

---

## 1. 正式寫下來

```
下層：  φ*(p)  ∈  argmax_φ  J(φ; p)
上層：  min_p   F(p, φ*(p))
```

逐符號讀：

| 符號 | 唸法 | 意思 |
|---|---|---|
| `argmax_φ J(φ; p)` | 「讓 J 最大的那個 φ」 | 在**給定**參考 p 之下，訓練到最好的策略 |
| `φ*(p)` | 「phi star of p」 | 上面那個最佳策略。**注意它是 p 的函數** —— 換一組參考，就會練出不同的策略 |
| `min_p F(p, φ*(p))` | 「找讓 F 最小的 p」 | 挑一組參考，使得「當策略對它練到最好時」的總目標最小 |

`J` 是強化學習的目標（累積獎勵），`F` 是上層的目標函數（差距 + 語意保真 + 可行性 + …，見 [README §4.1](../README.md)）。

### 下層目標 `J` 展開

```
J(φ; p) = E[ Σ_{t<H} γᵗ · r(s_t, a_t; ref_p) ]
```

| 符號 | 意思 |
|---|---|
| `E[·]` | 期望值 —— 對「隨機抽到哪段動作、哪具身體、從第幾幀開始」取平均 |
| `Σ_{t<H}` | 對 window 內的 H = 60 個控制步求和 |
| `γᵗ` | 折扣：第 t 步的獎勵打 `0.97ᵗ` 折。愈遠的未來愈不重要 |
| `r(s_t, a_t; ref_p)` | 第 t 步的獎勵。**`; ref_p` 表示它依賴上層產生的參考** |

---

## 2. 耦合是「雙通道」的

p 影響下層**兩條路**，不是一條：

```
          ┌─► 獎勵函數        r(s, a; ref_p)          參考動了，「做得好」的定義就動了
   p ─────┤
          └─► 初始狀態分布    RSI 從 ref_p[t0] 起始    參考動了，機器人每次的起點也動了
```

第二條容易被忽略但很重要：每個 window 開始時，我們把機器人的姿勢**直接寫成參考的第一幀**（這叫 RSI，Reference State Initialization）。所以移動參考，就等於移動了整個訓練的狀態分布。

後面 T2 那一項要處理的就是這條通道。

---

## 3. 核心難題：怎麼算 `dF/dp`

要用梯度下降更新 p，就得知道「p 動一點點，F 會怎麼變」。用連鎖律展開，會得到**三項**：

```
dF/dp  =  ∂F/∂ref · ∂ref/∂p              [T1]
       +  ∂F/∂τ · ∂τ/∂ref · ∂ref/∂p      [T2]
       +  ∂F/∂τ · ∂τ/∂φ · dφ*/dp         [T3]
```

`τ`（tau）是**機器人實際跑出來的軌跡**。

一項一項讀：

### T1 — 「參考動了，目標函數直接跟著動」

```
∂F/∂ref  ·  ∂ref/∂p
   ↑           ↑
目標對參考    參考對 p
的敏感度      的敏感度
```

這條路**完全不經過模擬器**。`F` 裡面的 `S`（語意保真）、`C`（可行性）、`prox` 都只是參考動作的函數，用 PyTorch 的 autograd 就能精確算出來。

**保留，而且是訊號主體。** 這正是「retargeting 用 torch 重寫成可微分」的價值 —— `∂ref/∂p` 就是 `apply_retarget` 的 autograd（見 [retarget.md](retarget.md)）。

> ⚠️ **但 T1 有一個洞。** `F` 裡的 `E_ext`（外力懲罰）和 `P`（物理合理性）只透過**模擬器**依賴 p，所以它們的 T1 **恆等於零**。純 T1 路徑**看不見外力作弊** —— 上層可以放心把參考弄難，讓下層用外力硬撐，完全不用付代價。這個洞由 T2 補。

### T2 — 「參考動了，模擬出來的軌跡也會變」

```
∂F/∂τ  ·  ∂τ/∂ref  ·  ∂ref/∂p
             ↑
         卡在這裡
```

`∂τ/∂ref` 的意思是「參考動一點點，模擬出來的軌跡會怎麼變」。這需要**對 MuJoCo 微分** —— 而 MuJoCo 不可微（沒有 MJX/jax 的話沒有替代路線）。

**不能忽略**，理由有二：

1. 上面說的 RSI 通道 —— 每個 window 的起點**字面上就是** `ref_p[t0]`
2. 外力作弊的那個洞

**解法：用 ES（演化策略）估計。** 見下面第 5 節。

### T3 — 「參考動了，策略最終會學成不一樣的樣子」

```
dφ*/dp  =  −(∇²_φφ J)⁻¹ · ∇²_φp J
```

這是**真正的** hypergradient —— 前兩項都只是「在**當前這個** φ 之下」的偏導，只有 T3 考慮了「換個參考會養出不同的策略」。

逐符號：

| 符號 | 意思 |
|---|---|
| `∇²_φφ J` | J 對 φ 的**二階**導數矩陣（Hessian）。「獎勵曲面在 φ 方向的彎曲程度」|
| `(·)⁻¹` | 那個矩陣的**反矩陣** |
| `∇²_φp J` | J 對 φ 和 p 的交叉二階導數 |

**捨棄。** 三個理由，按重要性：

1. **算不出來。** 這需要在一個有**接觸不連續**的物理系統上做「Hessian 反矩陣乘向量」。而且我們連一階的 `∇_φ J` 都只有 score-function 估計（高變異），二階估計的變異會隨 `1/σ⁴` 爆炸 —— σ 是探索噪音 0.05，`1/0.05⁴ = 160000`。每 iteration 15360 個樣本下完全不可用。
2. **這是標準做法。** first-order MAML、first-order DARTS、one-step-unrolled bilevel 全都是同一招（截斷 hypergradient）。已知在「下層對上層變數的反應夠平滑」時可行 —— 這裡由**硬 tanh box** 保證，因為 box 界定了獎勵目標最多能移動多遠。
3. **在時標分離下它通常只是幅度修正**，不是把下降方向的符號翻過來。

### 誠實的但書

> 捨棄 T3 之後，我們解的**不是** bilevel 問題。

實際在解的是這個交替最佳化（Gauss-Seidel）：

```
固定 φ_k，優化 p：   min_p F(p, φ_k)
固定 p_k，優化 φ：   φ_k ← RL(p_k)
來回輪流
```

**它的駐點和真 bilevel 的駐點不同。** 具體代價：**p 沒有動機去挑一個「現在很難、但能養出更好策略」的參考動作**。

對這個應用而言這是特性不是缺陷 —— 我們要的是**忠實且可行**的參考，不是課程規劃。而忠實與可行正是 T1 裡的 `S` 和 `C` 所編碼的。

## 4. TTSA：兩個時標

### 問題

`F(p, φ)` 的意思是「在**這個** φ 之下，參考該怎麼修」。如果 φ 還很爛，量到的差距反映的是「策略還沒學會」，不是「參考有問題」—— 上層會朝錯誤方向修。

理想上我們要 `φ ≈ φ*(p)`，也就是「下層已經對當前參考收斂了」。但每次動 p 就重訓一次下層顯然不可行。

### 解法：讓下層跑得比上層快很多

**TTSA** = Two-Timescale Stochastic Approximation（兩時標隨機逼近）。核心想法：

> 如果下層更新得夠快，從上層的角度看，下層**看起來就像已經收斂了**。

實作上用三個機制疊出這個「快」：

| 機制 | 設定 | 比例 |
|---|---|---|
| 學習率差 | `η_φ = 3e-4`、`η_p = 1e-5` | **30 : 1** |
| 更新頻率差 | 下層每輪更新，上層每 `K = 10` 輪才更新一次 | **10 : 1** |
| | | **有效 300 : 1** |

另外兩道保險：

- **proximal 項** `λ_prox · ‖u − u_prev‖²` —— 懲罰「這一步走太遠」（軟的）
- **信賴域** `‖Δu‖_∞ ≤ 0.02` —— 每步硬性夾住 u 的最大變化量（硬的）

（`‖·‖_∞` 讀作「無窮範數」，意思是「所有分量裡絕對值最大的那個」。所以這條的意思是：36 個分量**沒有任何一個**能一步動超過 0.02。）

### 還有一道更粗暴的：前 500 iteration 直接凍結 p

`upper_warmup_iters = 500`。在 φ 值得測量之前，`F(p, φ)` 沒有意義。凍結是「φ 接近 φ*(p)」這個理論假設的**實務替代品**。

### 誠實的但書

Borkar 的 TTSA 收斂條件是 `Σηₖ = ∞`、`Σηₖ² < ∞`、`η_p/η_φ → 0`。**用 Adam 時這些條件不嚴格成立**。理論在這裡只是「比例該取多少」的指引，真正提供穩定性的是上面那三個機制。**不宣稱任何收斂保證。**

## 5. T2 怎麼估：ES（演化策略）

### 基本想法

不用梯度。在參數上加隨機擾動，看目標變好還是變壞，反推該往哪走。

### 擾動誰

**擾動 p 的「輸出」`u ∈ R³⁶`，不是它的 ~7000 個權重。** 36 維才讓 ES 可行（ES 的樣本需求隨維度成長）。

### 公式

```
              1
  ĝ_u  =  ───────── Σ_g [ F̂_sim(u + σ_p ε_g) − F̂_sim(u − σ_p ε_g) ] · ε_g
           2 σ_p G_b   g
```

逐符號：

| 符號 | 意思 |
|---|---|
| `ε_g` | 第 g 個隨機方向（36 維標準常態） |
| `σ_p = 0.02` | 擾動幅度（pre-tanh 空間，約 0.4% gain 變化） |
| `F̂_sim(u ± σ_p ε_g)` | 把 u 往 `+ε` 和 `−ε` 各推一點，各跑一次模擬，量到的目標值 |
| `[前 − 後]` | 差值。**正的表示往 `+ε` 走更糟** |
| `· ε_g` | 用差值當權重，往那個方向加權 |
| `G_b` | 擾動組數，用來平均 |

白話：**每個方向都往前試一步、往後試一步，哪邊比較好就往哪邊加權**。這是一個有限差分的期望值形式。

算出 `ĝ_u` 之後：

```python
u.backward(gradient=ĝ_u)
```

對 autograd 來說，`ĝ_u` 就只是一個從外面塞進來的上游梯度，它會自動往下傳到 `RetargetNet` 的權重。

### 只作用在需要它的那部分

```
F_sim = λ_gap·G + λ_ext·E_ext + λ_phys·P
```

`S`、`C`、`prox` 已經有精確的 T1 了，不需要（也不該）再用高變異的 ES 估一次。

### 「反對稱」（antithetic）是什麼

`+ε` 和 `−ε` **成對**測試，而不是只測 `+ε` 跟不擾動比。兩次模擬共同的噪音會互相抵消，估計變異大幅下降。

### 成本是零

每 iteration 的配置：

```
9 具身體 × 2 對反對稱 = 18 組擾動，各佔一些 env slot
剩下的 env 是未擾動的對照組
```

那些 env **本來就要模擬**（每 iteration 固定跑 256 個），只是把其中一些的 `u` 換掉而已。**不需要額外的模擬。**

### CRN 是必要條件，不是優化

**Common Random Numbers**：同一對反對稱的兩次模擬，除了那個 `±σ_p ε` 之外，

- 哪一段動作
- window 從第幾幀開始
- RSI 的關節噪音
- 整條 `(60, 75)` 的動作噪音

**必須逐位元完全相同**。

> ES 的訊號在 `G` 上只有約 **10%** 的相對變化。沒有 CRN，rollout 本身的隨機性會把它完全淹沒 —— **加了比不加還糟**。

驗證方法：讓 `σ_p = 0` 的一對**必須產生逐位元相同的 `qpos` 軌跡**。

### 兩個穩定性細節

- **rank normalization**：形成 `ĝ_u` 之前，把那些 `ΔF_sim` 換成名次再加權。這樣估計不受 `F_sim` 的尺度漂移影響（訓練過程中 `G` 的絕對值會一直變）。
- **累積 K = 10 個 iteration 再更新**：和 TTSA 的 cadence 刻意設成同一個 K，讓每個上層步有足夠的擾動樣本。

## 6. 一個 iteration 到底做了什麼

```python
for k in 1..num_iters:

    # 1. 蒐集：256 個 window × 60 步，用當前的 (φ_k, p_k)
    ep = collect(...)                          # 其中一些 env 帶 ±σ_p ε 的擾動

    # 2. 下層：每一輪都更新
    φ_{k+1} = PPO(φ_k, ep)

    # 3. ES：累積 T2 的估計（不立刻用）
    accumulate_es(F_sim(ep))

    # 4. 上層：只有每 K=10 輪、且過了 warmup 才更新
    if k > 500 and k % 10 == 0:
        g = T1(精確 autograd) + ES累積/K + proximal
        Δu = clip(Adam(g), ±0.02)              # 信賴域
        p_{k+1} = p_k + Δu
```

## 7. 怎麼知道上層在作弊

上層唯一的可微梯度方向就是「把參考搬到機器人身上」—— 差距一樣會變小，但動作被破壞了。三道防線加一個決定性檢驗：

| 防線 | 在哪 | 怎麼運作 |
|---|---|---|
| **硬 tanh box** | [retarget.md](retarget.md) | 結構上做不到，不靠調權重。**最重要** |
| **`λ_fid : λ_gap = 3 : 1`** | `F` 的權重 | 兩項的穩定點是收縮估計 `ref* = (λ_gap·τ + λ_fid·src)/(λ_gap+λ_fid)`，代入即**參考最多往機器人漂 25%** |
| **`u_saturation`** | W&B `upper/` | `mean(|tanh(u)| > 0.9)`，超過 0.2 就是警報：p 貼在 box 牆上想出去 |

**決定性檢驗**：

```
G(τ, ref_p)   對「修正後的參考」的差距     ← 上層在最佳化這個
G(τ, ref_0)   對「原始 naive 參考」的差距   ← 上層碰不到這個
```

> **兩個都要降。** 只有前者降、後者不降，就是靠移動參考把差距關掉，機器人根本沒變好。

多算一次 torch FK 就能得到，成本可忽略。
